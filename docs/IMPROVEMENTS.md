## B. Yeni özellikler

1. ✅ **Sonuç geçmişi ve paylaşım** (Faz 5a)
   - *Adım 1 (hızlı):* Sonuçlar localStorage'a yazılır. "Geçmiş" sekmesi eklenir, JSON olarak dışa/içe aktarılabilir. Bu, yaz-planı'ndaki yedekleme kalıbının aynısı.
   - *Adım 2:* Backend'de SQLite (`sqlmodel` gerekmez, stdlib `sqlite3` yeterli). `POST /api/simulations` sonucu kaydeder, `GET /api/simulations/{id}` getirir. Paylaşılabilir `/r/{id}` sayfası.
2. ✅ (Faz 5b) **A/B karşılaştırma:** Aynı ürünün iki varyantı (farklı fiyat, başlık veya açıklama) yan yana iki segmentli halkayla gösterilir; fark tablosu eklenir.
3. ✅ (Faz 5b) **Fiyat duyarlılık eğrisi:** Simülasyon çekirdeği deterministik ve LLM'siz çalışıyor. `POST /api/price-sweep`, fiyatın %60 ile %140'ı arasında 9 noktada `run_simulation` çalıştırıp alım oranı ve gelir eğrisini döner. "Optimum fiyat" önerisi verir.
4. ✅ (Faz 5c) **Gerçek persona sohbeti:** Mevcut "AI chat" tek seferlik bir tartışma. `POST /api/persona-chat` ile seçilen personaya takip sorusu sorulur. Yanıtlar SSE ile akar; persona prompt'u yalnızca sunucuda kalır; rate limit uygulanır.
5. ✅ (Faz 5c) **Canlı ilerleme:** Sahte terminal logu yerine LangGraph adımları (`input_analysis → research → benchmark → simulate → debate`) SSE ile gerçek zamanlı gösterilir.
6. ✅ (Markdown + yazdır, Faz 5a) **Rapor dışa aktarımı:** Markdown veya PDF rapor: skorlar, persona tablosu, aksiyon planı. Tarayıcının `print` CSS'i ilk sürüm için yeterli.
7. ✅ (CI: Faz 5d) **Test ve CI**
   - pytest: aynı girdinin aynı skoru verdiği deterministiklik testleri, Pydantic sınır testleri, SSRF testleri, LLM mock'u ile graph testi.
   - Vitest ve Testing Library: `lib/api` hata yolları, halka bileşeni.
   - GitHub Actions: `ruff`, `pytest`, `npm run lint`, `npm run build`, `pip-audit`, `npm audit --omit=dev`. Dependabot.
8. ✅ (Faz 8c) **Gözlemlenebilirlik:** JSON log, `X-Request-ID`. `/api/health` yanıtına `{model, aiAvailable, serperAvailable}` eklenir.
9. ✅ (Faz 8d) **Kategori genişletme:** B3'teki Enum hazır olduktan sonra ayakkabı, çanta ve kozmetik kategorileri `category_rules.json` dosyasına eklenir.
10. ✅ (Faz 8e) **Dil tutarlılığı:** "TASK INTELLIGENCE" gibi İngilizce başlıklar ve ASCII'ye çevrilmiş Türkçe metinler temizlenir. Persona adları `personas.json` içinde Türkçe karakterli `displayName` alanıyla tutulur.
11. ✅ (Faz 7) **Tailwind 4 geçişi:** Dev araçlarındaki açıkları (S15) kapatır. CSS tabanlı config (`@theme`), `tailwindcss-animate` yerine `tw-animate-css`; DESIGN.md token'ları `globals.css`'e taşınır. Görsel regresyon için Faz 4'teki ekran görüntüleriyle karşılaştırma gerekir.
12. **Çoklu LLM sağlayıcısı (Gemini + Claude + GPT):** `llm_client` arkasında sağlayıcı katmanı; `generate_text`, `generate_json` ve `stream_chat` imzaları değişmez, servisler etkilenmez.
    - `LLM_PROVIDERS=gemini,anthropic,openai` sırası; bir sağlayıcı 429/5xx/zaman aşımı verirse sıradakine geçilir (Gemini kotası dolduğunda simülasyon ve sohbet durmaz). Anahtarı olmayan sağlayıcı atlanır.
    - Anahtarlar yalnızca sunucuda: `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`; model env ile sabitlenebilir. `/api/health` hangi sağlayıcıların hazır olduğunu döner. Yanıtlar `aiProvider`/`aiModel` alanı taşır.
    - Sistem talimatı + `<data>` bloğu (S5) her sağlayıcıda aynı kalır; JSON çıktı sağlayıcının yapılandırılmış çıktı özelliğiyle veya mevcut ayrıştırıcıyla alınır; SSE parçaları sağlayıcıdan bağımsız `delta` olaylarına çevrilir.
    - **Kapsam dışı:** Claude Pro/Max ve ChatGPT Plus gibi sohbet abonelikleri. Uygulama kullanıcılarına hizmet için resmî API sağlamıyorlar ve bu kullanım şartlara aykırı; yalnızca API anahtarı desteklenir. Kullanıcının kendi anahtarını tarayıcıdan girmesi (BYOK) de şimdilik yok: anahtar istemciden geçer, ayrıca saklama ve sızıntı riski doğurur.
    - Testler: sağlayıcı başına sahte HTTP yanıtlarıyla birim testi (ağ yok), zincirde geçiş testi, akış testi; gerçek anahtarla elle duman testi.
